# RCR_STD-42_decoder_plugin_for_sdrpp

*English: [README.md](README.md)*

[SDR++](https://github.com/AlexandreRouma/SDRPlusPlus) 用のアウトオブツリー・
デコーダプラグインです。日本の市町村**同報系**（防災行政無線）で使われている
POCSAG方式無線呼出システムの規格 **RCR STD-42** を復調・デコードし、シフトJIS
の漢字メッセージを含めてテキストとして表示します。

対象の電波は暗号化されていない、規格が完全に公開された2値FSK信号です。

| 項目 | 値 | 規格参照 |
|---|---|---|
| 変調方式 | 2値FSK、スペース = 中心 **+4.5 kHz**、マーク = 中心 **−4.5 kHz** | §2.1.6 |
| 最大周波数偏位 | ±5.0 kHz | §2.1.7 |
| 伝送速度 | **512 bps** / **1200 bps** | §1.1、§3.1 |
| 占有帯域幅 | 16 kHz以内、チャネル間隔 25 kHz | §2.1.4、§2.1.2 |
| 周波数帯 | 276.0125〜283.9875 MHz、320チャネル | §2.2.1 |
| 複局同時送信オフセット | 0、±250、±500、±750、±1000、±1250 Hz | §2.1.8 |
| プリアンブル | 「10」の連続 576ビット以上 | §3.2 |
| バッチ構成 | 同期コードワード + 8フレーム × 2コードワード = 17コードワード | §3.3 |
| 同期／アイドルコードワード | `0x7CD215D8` / `0x7A89C197` | 図3.4-2、図3.4-5 |
| 誤り訂正 | BCH(31,21) + 偶数パリティ、2ビットまで訂正 | §3.5 |
| 生成多項式 | x¹⁰+x⁹+x⁸+x⁶+x⁵+x³+1（`0x769`） | §3.5.2 |
| アドレス | 21ビット。下位3ビットはフレーム番号が担う | §3.3、§3.4.2 |
| メッセージ形式 | 数字（4ビット）、カナ英数字（8ビット）、漢字（16ビット） | §3.6 |
| 暗号化 | なし | — |

## 信号処理チェーン

```
VFO IQ（48 kHz、帯域幅 20 kHz）
 └─ 直交FM検波                                   → 瞬時周波数［Hz］
 └─ 速度別スライシングチェーン（Autoは 512 / 1200 / 2400 Bd を並列実行）
     ├─ ハミング窓LPF（遮断 1.1 × R_b）
     ├─ 中心／偏移トラッキング（搬送波オフセットを吸収し ±4.5 kHz を正規化）
     ├─ ゼロクロス方式DPLLビット同期（2次ループ：位相＋速度）
     └─ 硬判定                                    → ビット列
 └─ POCSAGフレーマ
     ├─ 同期コードワード探索（ハミング距離2以内、正転・反転の両方と照合）
     ├─ バッチ追従（SC + 8フレーム × 2コードワード）
     ├─ BCH(31,21) + 偶数パリティ（シンドローム表、2ビットまで訂正）
     └─ アドレス／メッセージ／アイドルの判別。アドレスは受信フレーム番号と再結合
 └─ メッセージデコード（§3.6は各文字をLSBから伝送するため、文字ごとにビット反転）
     ├─ §3.6.1 数字        4ビット／文字、図3.6-1
     ├─ §3.6.2 カナ英数字  8ビット／文字、JIS X 0201 → UTF-8
     └─ §3.6.3 漢字       16ビット／文字、シフトJIS（CP932）→ UTF-8
```

規格が定めていない2つの曖昧さは、利用者に押し付けず自動で解決します。

- **極性**：スペクトル反転するフロントエンドでは全ビットが反転します。フレーマは
  同期コードワードを `0x7CD215D8` とその補数の両方と照合し、合った方を採用する
  ため、「反転」スイッチを試行錯誤で探す必要がありません。
- **伝送速度**：STD-42は512 bpsと1200 bpsの両方を規定していますが、電波上に速度
  の表示はありません。1つずつ試して呼出しの先頭を取りこぼすのを避けるため、
  **Auto** では候補速度ごとに完全なチェーン（短いFIRとDPLLだけ）を並列に走らせ、
  フレーム同期が確立した方を採用します。

メッセージ形式も同様に信号中で示されません。**Auto** は3通りすべてでデコードし、
破綻なく変換できたものを選びます。漢字と判定するのは実際に2バイト文字が得られた
場合だけです（シフトJISはASCIIの上位互換なので、そうしないとASCIIのみのメッセージ
まで漢字扱いになってしまいます）。いずれもパネルから手動固定できます。

### 漢字のバイト順について

§3.6.3は「各文字を16ビットコードに変換し」「LSBから順次伝送される」と規定して
おり、字義どおりに読むとシフトJISの2バイト目が1バイト目より先に電波に乗ります。
一方、実際の装置は各**バイト**をLSB先頭で読み順に送る実装も多く、統一されていま
せん。そこでデコーダは両方を試し、不正文字が出ない方を採用します。特定の系統で
固定したい場合はパネルの **Kanji bytes** で `Normal` / `Swapped` を指定できます。

## ビルド

```sh
bash scripts/fetch-sdrpp.sh                       # SDR++ヘッダを external/ に取得
cmake -B build -S . -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
```

必要なのはC++17コンパイラとSDR++の**ソースツリー**だけで、SDR++本体のビルドは
不要です。`sdrpp_core` のシンボルはSDR++がモジュールを読み込む時に解決されます。
SDR++のヘッダが `<volk/volk.h>`、`<fftw3.h>`、`<GLFW/glfw3.h>` を include する
ため、コンパイル時のみこれらのヘッダが必要です（リンクはしません）。

```sh
brew install volk fftw glfw                                   # macOS
sudo apt install libvolk-dev libfftw3-dev libglfw3-dev        # Ubuntu
```

macOSではHomebrewのincludeディレクトリを自動検出します。

### セルフテスト

```sh
bash tests/run.sh
```

プリアンブル・バッチ・BCH符号化済みコードワードからなるSTD-42の送信信号を合成し、
±4.5 kHzで複素ベースバンドに変調（搬送波オフセットと雑音つき）して、元の日本語
テキストが復元できることを確認します。あわせてBCHデコーダを全1ビット・全2ビット
誤りパターンで検証し、同期／アイドルコードワードを図3.4-2・図3.4-5と、数字フォーマットのビット順を図3.4-4の「3681」の作例と照合します。

### キャプチャのリプレイ

`tests/replay.cpp` は、パネルの **Record IQ** で録ったベースバンドWAVを、プラグイン
本体と同じレシーバに通します。実際に受信した電波を再現可能なテストケースにできます。

```sh
c++ -std=c++17 -O2 -Isrc tests/replay.cpp src/demod/*.cpp src/pocsag/*.cpp -o build/replay
build/replay ~/.config/sdrpp/rcr_std42/capture.wav
```

## アイドル時のチャネルの様子

同報系の送信機は呼出しの合間も無音ではありません。例えば唐津の283.5365 MHzの局は、
**750 bpsの`1010…`アイドルパターンを±5 kHz偏移で常時送出**し、およそ14分に1回だけ
1秒ほどの1200 bps POCSAGバーストに切り替えて日付・時刻・曜日を同報しています。
つまり、正常な受信機はほとんどの時間「強い信号があるのにフレーム同期しない」状態で
待機することになります。

これが故障に見えないよう、パネルは状態を明示します。ゼロクロス間隔が規則的なときは
緑ランプで **「Channel idle — N bps 1010 pattern」** と表示し、実測レートを出します。
アイドルのレートがPOCSAGの伝送速度と違っていても異常ではありません（呼出しはその速度
では送られていないため）。

## SDR++への導入

プラグインをSDR++のプラグインディレクトリにコピーし、Module Managerで有効化して
インスタンスを作成します。SDR++はプラットフォームごとに決まった拡張子でディレクトリを
走査するため、ファイル名が重要です。

| プラットフォーム | ディレクトリ | ファイル名 |
|---|---|---|
| Linux | `/usr/lib/sdrpp/plugins/` | `rcr_std42_decoder.so` |
| macOS（アプリバンドル） | `SDR++.app/Contents/Plugins/` | `rcr_std42_decoder.dylib` |

macOS向けのリリース成果物は `rcr_std42_decoder-macos-universal.dylib` という名前です。
インストール時に `rcr_std42_decoder.dylib` へリネームしてください。

VFOをページングチャネルに合わせると、パネルに次が表示されます。

- **ステータスランプ** — 探索中／プリアンブル／信号ありフレーム同期なし／同期確立。
  検出した伝送速度と、極性が反転していたかどうかも表示します。
- **アイパターン** — スライサ入力を2シンボル周期に畳み込んで表示し、判定しきい値と
  サンプリング点を重ねます。ページング受信機のチューニング表示に相当します。
- **搬送波オフセット**、**周波数偏移**（§2.1.6より、正常なら4500 Hz付近）、
  **受信品質** を60秒間のスパークラインで表示。
- コードワード統計（無誤り／BCH訂正／棄却）とバッチ数・アドレス数・同期外れ回数。
- **最新の呼出し**と**Recent**一覧を日本語で表示。

**Address filter** はカンマ区切りの10進アドレス列です。空欄なら全件記録します。
同報系のように対象アドレスが事前に分からない場合は空欄のままが便利です。

### 日本語表示について

SDR++のフォントアトラスはRobotoのデフォルト範囲とキリル文字だけで構築されるため、
そのままでは日本語が豆腐（□）になります。本プラグインは日本語範囲をカバーする
フォントを追加し、起動時にアトラスを再アップロードします。フォントは自動検出します
（macOSはヒラギノ、UbuntuはNoto CJK / VL Gothic / IPAGothic）。見つからない場合は
インストールするか、

```sh
sudo apt install fonts-noto-cjk                                # Ubuntu
```

パネルでパスを直接指定してください。ImGuiのフォントアトラスはフレーム外でしか再構築
できないため、変更したパスは次回のSDR++起動時に反映されます。ファイル／TCP出力の
テキストは、パネルの描画可否にかかわらず常に正しいUTF-8です。

### 出力

デコードした各呼出しは次の形で出力できます。

- **テキストログ** — 1呼出し1行のgrepしやすい形式（ページングモニタのテキスト出力
  に相当）。
- **JSONL** — **ファイル**および／または**TCP**ポート（127.0.0.1）へ配信。テキスト、
  アドレス情報、呼出しごとの誤り数、生ペイロードを含みます。
  詳細は [docs/JSONL_FORMAT.ja.md](docs/JSONL_FORMAT.ja.md) を参照してください。

出力先の既定はSDR++の設定ディレクトリ（`~/.config/sdrpp/rcr_std42/`）で、設定は
インスタンスごとにSDR++の設定ファイルに保存されます。

## 適用範囲と法令について

RCR STD-42は暗号化されていないページングサービスの公開規格であり、本プラグインは
すでに空中に出ている信号を復調・デコードするだけです。日本では電波法第59条（秘密の
保護）により、自分宛でない通信の内容を窃用・漏洩することが制限されています。市町村の
同報系放送は住民向けの一斉放送ですが、受信するチャネルに何が適用されるかはご確認
ください。
